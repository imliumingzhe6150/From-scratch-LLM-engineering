## Structured Generation Evaluation

- Added immutable records for decoding policies, artifact identities,
  per-policy outputs, and complete evaluation metadata.
- Recorded prompt token IDs and counts, the model-visible empty-prompt fallback,
  generated token IDs and counts, visible token counts, explicit EOS versus
  length stopping, and the seed-reset policy.
- Added SHA-256 and byte-size identities for the checkpoint, vocabulary, and
  merge files so later runs can prove they used the same artifacts.
- Added `scripts/evaluate_generation.py` with three defaults: greedy,
  temperature 0.8/top-p 0.9, and temperature 1.1/top-p 0.95. Custom policies
  use the repeatable `NAME:TEMPERATURE:TOP_P` argument format.
- Wrote JSON atomically and kept evaluation separate from the core generation
  implementation so cached inference can reuse the same record format later.

The selected 5,000-step checkpoint was evaluated on CPU with prompt
`Once upon a time` and seed 42. Greedy, conservative, and diverse policies
sampled 159, 216, and 172 tokens respectively, including EOS. Greedy was the
most coherent but repetitive; conservative sampling added variety with a mild
logical contradiction; the diverse policy showed more grammatical and object
continuity failures. Full results and limitations are in `EXPERIMENTS.md`.
