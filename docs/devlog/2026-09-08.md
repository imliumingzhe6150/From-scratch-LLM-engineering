## KV-Cache Implementation

Completed Milestone 2's cache-aware model and generation path.

- Added `LayerKVCache` for the RoPE-rotated key and projected value tensors of
  one attention layer, plus model-level `KVCache` state with a shared sequence
  length and byte accounting.
- Added cached methods to causal attention, Transformer blocks, and
  `TransformerLM`. The API supports full-prompt prefill, multi-token cached
  chunks, and single-token decode while preserving arbitrary leading batch
  dimensions.
- Derived new RoPE positions from the cached sequence length. Cached chunks use
  a rectangular causal mask so earlier new tokens cannot attend to later ones.
- Defined a hard model context bound. Cached generation rebuilds from the latest
  context window when it fills, which exactly preserves the earlier uncached
  sliding-window semantics.
- Added a cache-aware generation function and made the generation CLI use it by
  default; `--uncached` retains the baseline path.
- Recorded the interface, complexity, memory formula, context policy, and future
  preallocation option in `docs/kv_cache.md` and decision record 003.

## KV-Cache Correctness

Added seven dedicated correctness tests covering cache shapes and storage,
multi-token chunk logits, incremental last-logit equivalence, arbitrary leading
batch dimensions, float64 dtype/device placement, invalid cache shapes and
layer counts, model context overflow, greedy equivalence across a shifted
context window, EOS stopping, and train/eval mode restoration.

Cached float64 chunk logits matched one full-sequence pass within `atol=1e-10`
and `rtol=1e-8`. Float32 incremental last logits use `atol=rtol=1e-5`.
